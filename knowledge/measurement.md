# Editable analytics and search context

Fill this in for the actual exports. Keep separate entries when providers,
filters, populations or periods differ.

## Source and scope

- Provider, property/site and source file names.
- Current and previous start/end dates; timezone and reporting lag.
- Filters and segments, including acquisition definitions.
- Row dimensions and grain: what exactly does one row represent?
- Completeness, export caps, thresholds, missing values and unavailable fields.
- Tracking changes, consent effects and other known limitations.

## Metrics

For every metric used, record its provider-specific definition and unit.
For rates, record the numerator, denominator and eligible population.
Distinguish users, sessions, landing-page sessions, page views and events.
State whether distinct users or other values overlap across rows.

## Outcomes

Name each outcome and explain how it is counted. Distinguish event counts
from sessions or users completing the outcome. Record attribution scope,
known duplicate events and changes to instrumentation.

## Comparison rules

Use equal completed periods and consistent filters when claiming movement.
Record changes to definitions that prevent a direct comparison. GSC query
evidence and on-site analytics do not establish individual query-to-outcome
attribution. Zero and unknown are different values.

Record the owner, data capture date and source documentation.
