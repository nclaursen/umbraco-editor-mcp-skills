# Editable page-block catalogue

This starts empty. Populate it from this site's actual schemas, exports,
rendered pages and editorial decisions using page-block-drafting.
Do not import another site's aliases, limits or component approval rules.

## Survey scope

Record the CMS/framework version when known, dates, source pages/files,
page types, cultures/variants and whether rendered output was inspected.
Describe what the sample does not cover.

## Component entry format

For each verified component record:

- Display name, technical alias and source for both.
- Editorial purpose and appropriate content shape.
- Fields, field types, required fields and accepted formatting.
- Verified length limits, nesting and item-count constraints with sources.
- Allowed page types and editorial approval status, with evidence.
- Media, alt text and link requirements.
- Observed copy lengths, labelled as observations rather than hard limits.
- Rendered headings and responsive behavior, only when inspected.
- When to use it, when to avoid it and relevant reference-page examples.
- Unknowns, conflicts, last review date and owner.

## Page patterns

Record patterns separately for product, landing, guide, article and other
observed page types. Separate page-level fields from blocks. Distinguish
recurring patterns from schema constraints and explicit editorial rules.

## Evidence labels

Use verified schema rule, editorial decision, observed practice, inferred
recommendation or unknown. Keep a source alongside each important rule.
Older usage alone does not establish permission to use a block in new pages.
