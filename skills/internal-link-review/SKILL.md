---
name: internal-link-review
description: Review selected pages for useful internal links, checking destination relevance, anchors and existing connections before proposing changes.
---

Read the selected source pages, content-map.md and audience context. Define the
reviewed section, languages and published/draft scope from the request. Use
available CMS read tools, supplied exports or saved pages; describe gaps in
coverage rather than claiming a whole-site audit from a sample.

Inventory existing links in rich text, buttons and content-picker fields.
Inspect candidate destinations before recommending them. A matching topic
or page name is not enough: identify the reader's next question and the
passage or component where the link would help. Avoid duplicate links that
add no navigation value and anchors forced into unrelated sentences.

Check the intended destination, language, published status and fragment when
available. Resolve relative URLs against the publication URL. Distinguish
broken links from inaccessible destinations. Content-picker IDs require a
verified URL mapping; do not invent URLs or assume a draft is public.

Return a short list of retain, add, replace or remove recommendations. For
each proposed change include the source page and field/passage, existing
link if any, destination, proposed anchor or field copy, reader benefit and
verification status. Include no change where the existing connection works.
Do not promise ranking gains or infer that every unlinked page is orphaned
without a complete inbound-link inventory.

Review is read-only. If implementation is explicitly requested, change only
the accepted fields through available tools, preserve unrelated content and
report the old/new values and destination checks. A link-review request does
not authorize publishing, redirects or changes to navigation configuration.
