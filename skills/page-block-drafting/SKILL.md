Use two modes as needed: learn the site's blocks or draft using an existing
catalogue. Locate the supplied knowledge/page-blocks.md, reference pages,
schema exports and brief. Read only the context relevant to the target page
type. This skill does not assume any CMS or live connection.

When using Umbraco CMS Editor MCP, read
[references/umbraco-editor-mcp.md](references/umbraco-editor-mcp.md) for the
documented tool sequence and its limits. Do not load it for other systems.

## Learn the blocks

Read a small representative set of pages of the requested type. When
authorized tools are available, inspect their content model and rendered
output; otherwise use supplied exports or code. Record each source, date,
culture and variant inspected, and the sample's coverage limits.

Catalogue actual component names and aliases, field types, required fields,
nesting, allowed page types, media/link needs and verified validation limits.
Separate schema rules from editorial rules and observed practice. Typical
copy lengths are not maximum lengths. A component seen on an old page is
not automatically approved for new pages. Do not infer semantic heading
levels or responsive behavior from component names or CMS JSON alone.

Describe each component's job, when it suits the content and when another
verified component is a better fit. Record page-level fields separately
from reusable blocks. Mark unknowns and conflicts instead of inventing
aliases, payload shapes, limits or allowed structures.

Write the catalogue and page-type patterns to the user's chosen knowledge
location. Keep sources and unknowns alongside each rule. If knowledge
creation was not requested, return the proposed catalogue for review.

## Draft the page

Read the brief, approved facts, audience and voice. Check catalogue freshness
against available evidence. Map each content unit to a verified block before
writing: purpose, block, fields, copy, source, media and constraints.

Use long-form components for sustained explanations and short-form
components for genuinely short or parallel content, where those components
exist. Do not force prose into cards, manufacture proof to fill a numbers
block or select components merely for visual variety. Explain any gap the
available components cannot support.

Draft field by field within verified rules. Preserve URLs, existing assets,
variants and unrelated fields during revision. Check heading hierarchy in
the rendered evidence, required fields, lengths, nesting and media needs.
Keep illustrative layouts separate from executable CMS payloads. Unknown
schema prevents a claim of payload validity; provide a content map instead.

Return the mapped draft, sources, checks and unresolved constraints. This
does not authorize schema changes, CMS writes or publishing. If a save is
separately authorized, use the exposed tools, preserve the original values,
re-read for concurrent edits and verify the saved result. Never report an
unperformed preview, backup or save as completed.
