# Maintenance review with Editor MCP

Scope the subtree and culture with `list-children` or `search-content`;
follow pagination where returned. Read full content with `get-page` and
`inspect-blocks`. Use `get-publish-status` for publication/schedules,
`list-versions` and `get-page-change-history` for recorded edits where useful.
A recent save does not prove factual freshness; an old page is not necessarily
obsolete. Neither version author nor last editor establishes content ownership.

Before proposing consolidation or archival, use `report-content-references`
for known inbound dependencies and `report-outbound-links` for outbound ones.
State coverage limits; these do not account for every external backlink or
rendered navigation path. Check supplied current facts and analytics rather
than treating missing data as no demand.

Return keep, update, investigate, merge or archive candidates with evidence,
material to preserve and known dependencies. This is a review queue, not a
delete list. If copy changes are requested, edit only those verified fields
with draft tools and read back. Do not automatically unpublish, delete, move,
rename, roll back or change redirects; those need explicit scope of their own.
